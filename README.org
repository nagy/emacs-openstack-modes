#+title:    emacs-openstack-modes - OpenStack resource modes for Emacs
#+author:   Daniel Nagy
#+language: en

Emacs major modes for displaying OpenStack resources.

Every OpenStack resource has a unique ID.  This repository starts
with one base mode that handles the ID, so that future
resource-specific modes can depend on it.

* Files

| File                      | Purpose                                                  |
|---------------------------+----------------------------------------------------------|
| =openstack-mode.el=       | Base major mode for OpenStack resources (ID handling)    |
| =openstack-cli.el=        | CLI layer: sync/async access to =openstack-program=      |
| =openstack-mode-tests.el= | ERT test suite for the mode                              |
| =openstack-cli-tests.el=  | ERT test suite for the CLI layer (mocked)                |
| =default.nix=             | Nix build with =melpaBuild=, runs ERT tests and checkdoc |
| =LICENSE=                 | AGPLv3                                                   |

* Usage

#+begin_src elisp
(require 'openstack-mode)
#+end_src

Commands:

- =M-x openstack-mode= -- put the current buffer into the mode
- =M-x openstack-display= -- display a resource by ID in a
  dedicated buffer
- =M-x openstack-copy-id= (=c=) -- copy the resource ID to
  the kill ring
- =M-x openstack-open-web= (=w=) -- open the dashboard page
  for the resource
- =M-x openstack-pop= (=p=) -- pop back to the buffer the
  resource was displayed from

Customization (=M-x customize-group openstack=):

- =openstack-buffer-name= -- name of the display buffer
- =openstack-web-base-url= -- base URL of the OpenStack
  dashboard
- =openstack-id-prefix= -- resource type path segment in the
  dashboard URL
- =openstack-program= -- path to the =openstack= command line
  client (python-openstackclient)

* OpenStack CLI

The package interfaces with OpenStack through the
=python-openstackclient= command line program (nixpkgs package
=openstackclient-full=).  The Nix build substitutes the default
value of =openstack-program= with the store path of that program,
so users do not need to customize it.  The client needs standard
OpenStack authentication (e.g. an =openrc= file or environment
variables).

All CLI access goes through the =openstack-cli= library, which
mirrors the =jsonrpc= library's design: a synchronous
=openstack-cli-request= and an asynchronous
=openstack-cli-async-request=.

#+begin_src elisp
  ;; Synchronous: returns parsed JSON (hash table or list)
  (openstack-cli-request '("server" "show" "some-id"))

  ;; Asynchronous: callbacks when the process finishes
  (openstack-cli-async-request
   '("server" "list")
   :success-fn (lambda (result) ...)
   :error-fn (lambda (err) ...))
#+end_src

The =--format json= option is appended automatically.  Commands
that produce no output (e.g. =delete=) parse to nil; non-zero
exit or unparseable output signals =openstack-cli-error= (sync)
or calls =error-fn= (async).

* Design

=openstack-mode= is the base mode.  It keeps a buffer-local
=openstack--id=, renders a minimal view of the resource, and
provides ID handling.  Future modes (servers, volumes, images,
networks, ...) should derive from it and set
=openstack-render-function= to their own renderer:

#+begin_src elisp
  (defun openstack-server-render (id)
    "Render a server resource."
    ...)

  (define-derived-mode openstack-server-mode openstack-mode
    "OpenStack Server"
    "Render server-specific fields, inheriting ID handling."
    (setq-local openstack-render-function #'openstack-server-render))
#+end_src

* Building

#+begin_src sh
nix-build default.nix
#+end_src

The build byte-compiles with warnings as errors, runs the ERT test
suite, and runs checkdoc.
